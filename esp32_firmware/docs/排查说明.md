# ESP32 Car 故障排查手册

---

## 1. vTaskDelay 无法用于 UART 指令间隔（核心故障）

### 症状

去掉 `ESP_LOGI` 串口日志后，无论 `vTaskDelay` 设多长（3/4/5/6/8ms），电机完全不动。但加回日志立刻正常。

### 测试历程

| 方案 | 结果 |
|------|------|
| `vTaskDelay(3ms)` 无日志 | ❌ 不动 |
| `vTaskDelay(4ms)` 无日志 | ❌ 不动 |
| `vTaskDelay(5ms)` 无日志 | ❌ 不动 |
| `vTaskDelay(6ms)` 无日志 | ❌ 不动 |
| `vTaskDelay(8ms)` 无日志 | ❌ 不动 |
| `vTaskDelay(3ms)` + 关 poll | ❌ 不动 |
| `uart_wait_tx_done` + `vTaskDelay` | ❌ 部分动/不稳定 |
| `ESP_LOGI` + `vTaskDelay(3ms)` | ✅ 始终正常 |
| `for` 循环忙等 | ✅ 正常 |
| `ets_delay_us(500)` | ✅ 正常，最终采用 |

### 根因

`vTaskDelay` 会让 CPU 进入空闲状态（WFI），ESP32 总线矩阵在空闲时降功耗，导致 UART DMA 传输时序在 512k 高速波特率下不稳定，驱动板接收到错乱字节。

`ESP_LOGI` 写串口（115200 波特率）期间 CPU 持续活跃，恰好"掩护"了指令间隔。这不是日志本身的功能，而是日志产生的 **CPU 忙等副作用**。

### 结论

**该电机驱动板在 512k 波特率下，指令间隔必须用忙等（`ets_delay_us` 或 `for` 循环），不能用 `vTaskDelay`。**

### 最终方案

```c
// uart_motor.c — uart_send()
#include "rom/ets_sys.h"

static void uart_send(const uint8_t *data, size_t len)
{
    xSemaphoreTake(s_uart_mutex, portMAX_DELAY);
    uart_write_bytes(UART_NUM_1, data, len);
    xSemaphoreGive(s_uart_mutex);
    ets_delay_us(500);  // 必须忙等！vTaskDelay 不行！
}
```

四条指令间隔 500us，M1 到 M4+触发 总延迟 2ms。

## 2. 电机完全不响应（vTaskDelay 被删除）

**症状**：串口日志显示 `SENT: M1=xxx ...`，但电机不动。

**根因**：`uart_motor_joystick()` 循环内的 `vTaskDelay(pdMS_TO_TICKS(3))` 被删。

**解决**：保留延时（现改为 `ets_delay_us`），不可去除。

---

## 3. 电机停止后仍有部分电机微动

**症状**：松手后部分电机持续小幅转动。

**根因**：多线程竞态。`motor_cmd_task` 和 WS 处理线程共享 UART，stop 与 joystick 指令互相穿插。

**解决**：`uart_motor_joystick()` 循环内每轮检查 `s_stop_override`，stop 触发后立即中止。

---

## 4. 摇杆回中后电机微动（衰减爬行）

**症状**：键盘松键后摇杆平滑回中过程中电机低速微动。

**根因**：摇杆衰减产生 0.02~0.04 小值，对应 RPM=10~20。

**解决**：`max_abs < 0.03f` 时直接 return，不发送。

---

## 5. 偏航角漂移

**症状**：平移后回到原位偏航角有十几度偏移。

**根因**：陀螺 Z 轴残余零偏持续积分。

**解决**：积分前加死区，`|gyro_z| < 0.5°/s` 禁止积分。

---

## 6. 俯仰/横滚在平移时大幅变化

**根因**：加速度计无法区分重力和平移加速度。

**结论**：物理限制，无磁力计无法消除。只使用偏航角做控制。

---

## 7. 无应答校验导致同步不稳定

**症状**：只发不收，部分电机漏指令。

**根因**：512k 高速下无 ACK 校验，无法确认每路电机缓存成功。

**注意**：本项目驱动板在速度模式（0xF6）下读应答不稳定（读到 0xFF 空闲字节移位），应答校验方案暂不可用。同步依赖 sync=0x01 + 触发 `00 FF 66 6B` + 忙等间隔保证。

---

## 8. WHO_AM_I 读取为 0x70

**根因**：MPU6050 clone 模块，寄存器值非标准 0x68。

**结论**：不影响功能，代码不可做 `who != 0x68` 硬检查。
