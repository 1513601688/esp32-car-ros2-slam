# ESP32 小车项目功能说明

## 1. 项目概览

本项目运行在 `ESP32-S3` 上，目标是完成一个四轮全向底盘的本地控制、ROS 通信、IMU 采集和前端遥测显示。

当前版本的主要能力：

- 通过 `ROS` 串口接收 `cmd_vel` 速度指令
- 通过电机串口控制四个轮子的运动
- 周期读取四个轮子的编码器脉冲
- 读取 `JY901` IMU 数据
- 计算并回传底盘 `Vx / Vy / Yaw`
- 通过 `HTTP + WebSocket` 向前端页面实时推送状态
- 支持前端执行参数设置、脉冲归零、Yaw 归零、停车
- 保留超时自动停车机制，避免控制链路异常时底盘继续运动

---

## 2. 目录内核心文件

### `main.c`

主入口文件，负责：

- 初始化 NVS
- 初始化 WiFi
- 初始化电机 UART
- 初始化 IMU
- 初始化 ROS 串口
- 初始化 Web 服务
- 创建核心 RTOS 任务

### `wifi_manager.c / wifi_manager.h`

负责：

- 连接指定 WiFi
- 处理掉线重连
- 启动 `mDNS`
- 让浏览器可通过 `esp32car.local` 访问设备

### `uart_motor.c / uart_motor.h`

负责：

- 通过 `UART1` 与电机驱动板通信
- 把归一化速度命令转换成四轮速度命令
- 查询编码器位置
- 管理加速度、最大转速
- 实现超时自动停车
- 通过 `Mutex` 保护电机串口总线

### `imu_sensor.c / imu_sensor.h`

负责：

- 通过 `I2C` 读取 `JY901`
- 获取加速度、角速度、姿态角
- 输出统一的 `imu_data_t`

### `ros_serial.c / ros_serial.h`

负责：

- 通过 `UART2` 接收 ROS 下发的 `cmd_vel`
- 把 `vx / vy / wz` 转成底盘归一化控制量
- 周期回传 `ODOM,vx,vy,yaw`

### `web_server.c / web_server.h`

负责：

- 启动 HTTP 服务
- 提供 WebSocket 实时通信
- 接收前端控制命令
- 维护共享遥测状态
- 计算里程计和 Yaw 输出
- 周期向前端广播 JSON 数据

### `car_config.h`

集中管理与硬件和车体结构相关的参数，例如：

- 电机 UART 引脚和波特率
- 轮径
- 轮心到车体中心距离
- 编码器每圈脉冲数
- 编码器方向标定
- IMU Yaw 方向符号

## 3. 当前 RTOS 结构

项目当前保留 4 个 RTOS 任务和 1 个周期定时器。

### RTOS 任务

#### `motor_poll_task`

职责：

- 每 `25ms` 轮询一个电机的编码器数据
- 周期执行 `uart_motor_watchdog()`
- 轮询完四个电机后更新前端和 odom 使用的编码器状态

说明：

- 这是当前底盘数据采集的核心任务
- 超时自动停车逻辑已经合并到这个任务里，不再单独开 watchdog 任务

#### `imu_poll_task`

职责：

- 每 `20ms` 读取一次 IMU
- 把最新 IMU 数据写入共享遥测状态

#### `ros_rx_task`

职责：

- 监听 `UART2`
- 接收 ROS 下发的 `cmd_vel`
- 直接调用电机控制接口

#### `ros_tx_task`

职责：

- 每 `100ms` 发送一帧 ODOM 文本到 ROS 上位机

---

### 周期定时器

#### `telemetry_timer_cb`

职责：

- 每 `100ms` 读取共享遥测快照
- 通过 WebSocket 向前端推送 JSON 数据

说明：

- 这个定时器只负责广播前端数据
- 不再承担 watchdog 检查职责

---

## 4. 主要数据流

### 4.1 ROS 控制链路

`ROS 上位机 -> ros_rx_task -> uart_motor.c -> 电机驱动板`

说明：

- ROS 下发的 `cmd_vel` 被解析为 `vx / vy / wz`
- 再转换成底盘使用的归一化控制量
- 最终发给四个电机

### 4.2 编码器遥测链路

`电机驱动板 -> motor_poll_task -> web_server.c 共享状态 -> 前端 / ros_tx_task`

说明：

- 编码器脉冲用于显示轮子状态
- 同时参与底盘 `Vx / Vy` 计算

### 4.3 IMU 遥测链路

`JY901 -> imu_poll_task -> web_server.c 共享状态 -> 前端 / ros_tx_task`

说明：

- IMU 提供加速度、角速度和姿态角
- 项目内部使用 `gyro yaw` 作为 ROS 和前端输出的主要 Yaw 依据

### 4.4 前端控制链路

`浏览器 -> WebSocket 回调 -> uart_motor.c / web_server.c`

前端当前可触发的动作：

- 设置加速度
- 设置最大速度
- 脉冲归零
- Yaw 归零
- 停车
- 兼容摇杆控制命令

## 5. 共享状态与并发保护

### 电机 UART 互斥

位置：

- `uart_motor.c`

作用：

- 防止“发电机命令”和“查编码器”同时访问同一条串口

### 遥测状态互斥

位置：

- `web_server.c`

作用：

- 防止 IMU 任务、电机轮询任务、前端定时广播、ROS 回传同时读写同一份状态

当前共享状态主要包含：

- 电机转速
- 编码器位置
- IMU 数据
- 里程计速度
- 输出 Yaw

## 6. 看门狗机制

项目保留的是“业务级超时停车”，不是芯片硬件看门狗。

### 触发逻辑

- 如果一段时间内没有收到有效运动命令
- `uart_motor_watchdog()` 会触发自动停车

### 当前实现方式

- 由 `motor_poll_task` 周期调用检查
- 不再单独创建 `wdt_task`

### 设计目的

- ROS 异常退出时防止底盘继续跑
- 串口链路断开时防止维持旧速度
- 提高运动控制的安全性

## 7. 关键协议

### ROS 输入协议

UART2 接收：

- 帧头 `0xAA`
- `float32(vx, vy, wz)`，小端
- 帧尾 `0x55`

### ROS 输出协议

UART2 发送：

```text
WHEEL,<stamp_ms>,<vx>,<vy>,<wz>\n
IMU,<stamp_ms>,<ax>,<ay>,<az>,<gx>,<gy>,<gz>,<roll>,<pitch>,<yaw>\n
```

轮式里程计和 IMU 独立发送，供 ROS 2 `robot_localization` 融合。`vx / vy / wz` 来自编码器运动学解算；IMU 角速度和姿态使用弧度单位。

### 前端 WebSocket 数据

主要字段包括：

- `wheels`
- `pulses`
- `imu`
- `odom`

## 8. 当前代码结构特点

当前版本已经做过一轮 RTOS 结构精简，主要特点是：

- 保留必要的并发任务，不做过度拆分
- 删除了网页命令中转队列任务
- 删除了独立 watchdog 任务
- 保留超时停车机制
- 保留前端、ROS、电机、IMU 四条核心链路
- 共享状态统一集中在 `web_server.c`

## 10. 一句话总结

这个项目本质上是一个“ESP32 本地控制层”：

- ROS 负责下发速度目标
- ESP32 负责驱动电机、采集编码器和 IMU
- Web 前端负责实时显示和少量本地控制
- RTOS 用来把采集、控制、回传、前端广播拆开，保证系统运行稳定且易维护

## 11. 当前标定结果

截至当前版本，底盘的 `vx / vy / wz` 已完成一轮实车标定，平移和旋转在常用速度段内已经基本可用。

### 11.1 当前关键参数

位置：
- `main/car_config.h`

当前实车标定参数：

```c
#define CAR_CMD_SCALE_VX            0.62f
#define CAR_CMD_SCALE_VY            0.62f
#define CAR_CMD_SCALE_WZ            0.47f

#define CAR_ODOM_SCALE_VX           1.90f
#define CAR_ODOM_SCALE_VY           1.85f
#define CAR_ODOM_SCALE_WZ           1.00f

#define CAR_CMD_LINEAR_DEADZONE     0.010f
#define CAR_CMD_ROT_DEADZONE        0.006f
#define CAR_MOTOR_MIN_EFFECTIVE_RPM 10U
```

### 11.2 标定后的实际结论

- `vx` 方向：实际车速与 ROS / 前端回传速度已经基本一致
- `vy` 方向：经过再次收敛后，实际横移速度与回传速度已经基本一致
- `wz` 方向：`0.2 / 0.4 / 0.8 rad/s` 在短时测试中已经能明显拉开，且整体误差可接受
- 低速旋转：保留了较小噪声死区，同时通过最小有效转速保证小角速度可以起转

### 11.3 后续维护建议

- 不要随意改动以上标定参数，除非轮径、减速比、编码器参数、供电或负载发生变化
- 如果更换轮胎、车轮、驱动器或底盘结构，应重新做一轮 `vx / vy / wz` 实车标定
- 如果后续要继续优化旋转低速线性，建议做“分段角速度补偿”，不要直接再改全局 `CAR_CMD_SCALE_WZ`
